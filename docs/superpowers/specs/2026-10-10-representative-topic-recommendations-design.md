## Observation window and activity channels

Default window: preceding 24 calendar months through one captured as-of instant, using the Washington DC civil date consistent with congress/current.py. Date fields use the half-open interval [calendar-month-subtracted capture date, capture date + one day); timestamp fields also require <=captured_at. Clamp nonexistent month-days using standard-library calendar/date. Represent start/end and capture time in responses. Baseline terms are year-derived, with no precision/completeness provenance; do not use them as exact service cutoffs or assume full-window service. Keep dated observed events within the window, flag service_history_unknown/term_precision_year_derived, and suppress service-days/monthly rates. A date conflict with coarse terms is a source uncertainty, not proof the observed event is impossible. Exact exposure normalization is deferred until a separately approved persisted verified-date/provenance contract exists. Within-channel topic shares normalize observed activity volume, not unobserved days in office.

Use existing ingested federal HR/S metadata only for first-version measures. Separate fields count parsed joint/simple/concurrent resolutions and unrecognized prefixes when present, but exclude them from the HR/S classification and rank vector. If none are ingested, resolution coverage is `unsupported`, count is null, not zero. No external requests occur during ranking.

Preserve channels, never describe their sum as support:

1. **Introduced/sponsored**: sponsor FK and introduced_at within the window. One bill identity per representative; missing introduction date contributes to a missing-date count only.
2. **Active cosponsorship**: dated BillCosponsor with withdrawn_at null at capture and sponsorship_date in the window. Missing date is unknown; withdrawn relationships are separately counted/excluded. Wording says “active cosponsorship recorded as of [date]”, not “introduced”. Current withdrawal state cannot reconstruct historic support.
3. **Recorded final-passage positions**: window-dated Vote with HR/S bill FK, known session_number and source URL. Normalize question whitespace/case and require exact allowlist `on passage`, `on passage of the bill`, `on the passage of the bill`. Any other question is excluded from support-rate summaries and remains ordinary vote evidence. A narrower allowlist sacrifices recall safely; unit fixtures and actual persisted question samples must verify it before implementation claims. Do not treat a successful procedural vote or final vote result as the representative's position.

Count each bill at most once per sponsor/cosponsor channel. Vote evidence is separate raw selected-bill evidence, never a recurring-topic channel or a repeat-title support count. For multiple allowed passage votes on one bill, select the latest allowed dated roll separately per chamber, then vote ID descending. For each representative only a real member record establishes a recorded position; a missing position on that selected roll stays unknown and never falls back to an older yes. If records exist in both chambers, retain one latest dated position for that representative/bill and mark the cross-chamber history; ambiguous duplicate source records are excluded. Do not manufacture eligibility or missing-vote denominators from the year-derived service intervals. Present/not_voting/other, missing positions and uncertain eligibility are separate from the decisive yes+no denominator. Earlier rolls can appear as bounded source history, not another observation. Unknown-source/session legacy duplicates are excluded with an uncertainty count. Vote completeness is always unknown/incomplete in this helper until the existing authoritative per-chamber discovery coverage contract can be attached without N+1; do not assert complete from observed rows alone. Voting agreement, vote positions and yes rates do not influence recommendation ranking.

## Duplicate/reintroduced bills and taxonomy overlap

First deduplicate by canonical existing Bill ID/session/number and unique sponsorship/cosponsorship/roll constraints. Report that authoritative family linkage is unavailable. The following raw/repeat-group activity statistics and recurring classification apply only to sponsor and active-cosponsor channels. Vote evidence retains separate raw selected-bill positions; do not merge conflicting positions across repeat-title groups.

Run a conservative repeat sensitivity analysis in addition to identity counts: within each representative/channel, group bills with identical NFKC/casefold/whitespace-normalized title and the same known originating sponsor, across sessions/numbers. Do not strip substantive digits or fuzzy-match titles. Unknown sponsor or blank title keeps independent bill identities. These are **possible repeat-title groups**, never asserted companion/reintroduction families. Each group contributes one observation. Topic weights in a group are the minimum per-member raw weight for that topic (missing topic has weight zero): only intersection topics survive, and retained weights are never renormalized. Example: {Health,Education} and {Health,Transport} leave Health weight 0.5, not 1; empty intersection contributes unknown topic mass. This prevents grouping itself from inflating an observation's topical mass. The raw and repeat-group statistics both appear in evidence, and thresholds must pass both. Neither is a statistical lower bound on population interest. This reduces obvious repeat-count inflation while acknowledging missed differently titled reintroductions and potential false merges.

For a raw bill with k usable specific tags, allocate `1/k` topical mass to each. For a repeat group, use the minimum raw member weight just defined. Exclude `general-legislation`, nonpositive and nonfinite confidence exactly as in the bill design's shared usable-edge predicate. A broad multi-tag bill contributes total mass one, not k independent instances; a sensitivity group may contribute less than one. Confidence is not a probability. Denominator includes all dated eligible bills/groups in that channel, including those with missing/fallback tags; missing tags reduce measured coverage rather than inflating a share over a tiny tagged subset.

For representative r, channel j, topic t:

```text
n(r,j) = distinct dated eligible HR/S bill identities (or repeat groups)
m(r,j,t) = sum(raw bill weight or repeat-group minimum weight for topic t)
a(r,j,t) = m(r,j,t) / n(r,j), when n>0; otherwise null
c(r,j,t) = count of distinct identities/groups carrying topic t
coverage(r,j) = tagged identities/groups / n(r,j), when n>0
```

Show n, c, fractional m, a, coverage, missing-date count and example bill identities. Missing-date counts are scoped to bills whose known Congress interval intersects the window and identified separately from dated window n; unknown/invalid session dates are another uncertainty count. Never allocate a missing event date to a specific window. Unknown n is null; an observed n=0 is explicitly zero observed dated records, not evidence of opposition. Profiles are descriptive of the ingested subset; bill/cosponsor completeness is not established by vote completeness.

## Configurable X, minimum evidence and wording

Proposed configurable defaults (policy choices to evaluate, not empirically validated constants): `window_months=24`, topic share X=0.20, minimum channel observations=20, minimum distinct on-topic observations=5, minimum usable-tag coverage=0.80. Validate 0<X<=1, min evidence positive, window 6..48 months; expose resolved values/version in API. Settings are server-owned, not arbitrary private-endpoint URL filters.

Both share/coverage settings must parse as finite decimal strings with 0<value<=1 (reject NaN/Infinity, zero, negatives and values above one); observation floors/window are positive integers, not booleans. Reject invalid policy at startup/checks, never silently fall back. The vector channel weights and evidence discount remain versioned server policy.

Use standard-library Fraction for raw 1/k weights, group minima, masses, shares, coverage and threshold comparisons; parse X/coverage thresholds from decimal strings to exact fractions. Never compare sequential floating sums to X. Boundary fixture: 18 of 30 bills carry Health among three tags each, all 30 tagged: mass=6 and share=1/5 exactly, qualifying at X="0.20". Plain float thirds could incorrectly reject it.

A recurring channel-topic qualifies only when both raw-identity and conservative repeat-group calculations satisfy all four thresholds. Examples: 5 of 20 single-tag sponsorships qualifies (25%); 20 of 200 does not (10%); 5 of 20 with five tags each does not (5% fractional share); five repeated-title bills forming one group fail minimum distinct evidence. A new member with 3 bills has visible evidence and `insufficient_history`; it cannot receive a recurring label.

Use “Frequent sponsor of bills tagged Health” and “Frequent active cosponsor of bills tagged Health”, always qualified “among ingested bills, [window]”. Do not use the general label “strong supporter” or “pet topic”: source activity does not establish an enduring stance. Threshold result is `recurring_observed_activity`, not a latent preference/probability. Return at most five recurring topics per representative/channel ordered by conservative a descending, conservative c descending, topic ID ascending; keep full per-topic data accessible for ranking and profile presentation.

For vote evidence only, report `yes / (yes+no)` with the observed denominator, selected source questions and coverage qualifier (null when denominator zero). Do not classify a broad supporter using it in v1: many topics/actions are correlated, the ingested sample is selected, and recorded passage votes do not establish stance on every tagged provision. Missing records, unknown questions and incomplete discovery produce explicit unknown/incomplete status. Service-days/monthly activity fields are null with reason term_precision_unknown in this baseline; do not use year-derived January-3 dates to invent exact exposure or a monthly rate. Complete verified service provenance could support n*30.4375/union-clipped-service-days in a future approved version, but is unavailable now.

We considered binomial intervals such as Wilson's [original 1927 paper](https://www.jhanley.biostat.mcgill.ca/c607/ch08/wilson_jasa_1927.pdf), DOI 10.1080/01621459.1927.10502953, but do not adopt them here: fractional topic mass, correlated/reintroduced legislation and selected ingestion do not provide a justified independent binomial sample. Report raw/conservative sensitivity, sample counts and coverage instead of pseudo-statistical certainty. No population-level confidence claim is made.

## Representative activity vectors and user profile

For ranking use conservative repeat-group sponsor and active-cosponsor shares only. Keep channel measures separate in explanations. Construct a topic activity vector `v_r` using weights 0.6 sponsor / 0.4 active cosponsor, normalized across channels with n>0; a missing channel is unknown and does not count as opposition. Sum of v_r is at most one because untagged mass remains absent. A mixed scalar vector is a discovery aid, not a support score. Public fields retain original channel counts/shares, never replace them with the mixture.

Ranking eligibility: is_current true, not already followed by the user, at least five conservative distinct HR/S observations in the union of dated sponsor/cosponsor channels, at least three conservative distinct units carrying a matched topic, and positive profile overlap. Build union evidence by unique bill IDs first, then the same repeat-title grouping across that union (not a sum of channel group counts); sponsor+cosponsor on one bill counts once. Use minimum member tag weights there too. Matched topics are the union of explicit usable followed topics and topics with positive weight in the followed-representative reference vector, intersected with positive candidate vector/group weights. A unit counts toward the matched-evidence floor when at least one of those topics has positive weight, not once per tag. Records with missing dates cannot meet minimum evidence. Current status is source metadata as-of capture, not a prediction of future officeholders. Fewer than five eligible matches returns fewer than five.

The user profile uses **only explicit TrackedTopic and TrackedLegislator** records; bill-derived interests, saved searches, transient filters, state, party, donors, biography, sensitive traits and vote positions are excluded. Remove fallback topic follows. For each usable followed representative, construct the same v_r with at least five conservative known-topic union observations; average those vectors equally, not by the representative's total volume. Followed former representatives can supply a reference if they have enough dated window evidence, so the public catalog includes all representatives with window activity, not only the current recommendation roster. If no followed representative has enough data, representative-lookalike facet is unavailable rather than zero/negative. Do not infer ideology from representative similarity.

For candidate r:

```text
T_r = sum(v_r[t] for distinct explicitly followed usable topics t)
C_r = cosine(v_r, equally averaged usable followed-representative vectors)
      (0 if either vector norm is zero)
A_T = 1 when explicit usable followed topics exist, else 0
A_R = 1 when a usable followed-representative reference vector exists, else 0
cross_r = min(T_r,C_r) if A_T=A_R=1, otherwise 0
B_r = 0.8*(0.7*T_r + 0.3*C_r)/(0.7*A_T + 0.3*A_R) + 0.2*cross_r
E_r = tagged distinct conservative union units / (all union units + 20)
S_r = B_r * E_r
```

If both facets unavailable, return explicit cold start/insufficient-metadata state. E_r is a disclosed evidence-stability/coverage discount, not a probability or support likelihood. It gives larger usable evidence a diminishing score advantage, so equal topic profiles with different sample sizes need not tie; it deliberately gives no additive raw-count relevance boost. This shrinkage policy requires sensitivity evaluation and is not statistical confidence. Missing cosponsor channels are never called absent support. Keep vectors/T/E as exact fractions. Cosine alone uses sorted topic IDs and math.fsum over finite float components; quantize it to six decimals using ROUND_HALF_EVEN before conversion back to a fractional millionth. Compute B/S exactly from those inputs, quantize S to integer millionths with exact half-even rounding, and use those same values for response and ranking. MMR uses six-decimal cosine and exact 9/10,1/10 weights with the same half-even boundary. Explicitly test rounding boundaries; this is deterministic policy for the supported runtime, not arbitrary real-number precision. No learned or collaborative matrix.

Select at most five with MMR `0.9*S_r - 0.1*max(cosine(v_r,v_selected))`. Similarity uses topical activity only; no party, donor or vote-alignment diversification. Base ties: quantized S descending, number of distinct matched explicit topics descending, tagged conservative union evidence descending, bioguide_id ascending, ID ascending. MMR ties use same tuple. No matching candidates means empty, not popular figures or electoral endorsements. Recommendations are titled “Representatives to follow” with caption “Shared topics in recorded legislative activity”.

First selection has no selected neighbor, so maximum similarity and penalty are zero. Never compare a candidate to itself. Subsequent cosine comparisons use exactly the same sorted/quantized routine as the profile comparison.

## Research cross-reference and implementation plan extension

The core [Pazzani/Billsus content-profile framing](https://link.springer.com/chapter/10.1007/978-3-540-72079-9_10) applies to topical activity descriptions and explicit user follows. Cosine similarity between metadata vectors is content similarity; it is not Sarwar/Linden collaborative filtering. [Carbonell/Goldstein MMR](https://www.cs.cmu.edu/~jgc/publication/The_Use_MMR_Diversity_Based_LTMIR_1998.pdf) supplies the greedy relevance/redundancy equation.
